# Задание 4.3. Телефонная книга на бинарном дереве поиска

## Назначение

Телефонная книга реализована на бинарном дереве поиска (BST). Для контактов доступны добавление, просмотр, редактирование, удаление, визуализация дерева и сортировка отображаемого списка. Предусмотрена ручная и периодическая автоматическая балансировка.

Инструкция относится к обновлённой версии задания 4.3 с пунктами меню `5`–`8` и константой `PHONEBOOK_BALANCE_INTERVAL` в `contacts.h`.

## Организация проекта

- `main.c` — меню, ввод/вывод, выбор сортировки отображаемых контактов.
- `contacts.h` — структуры, константы, объявления функций.
- `contacts.c` — работа с деревом, поиск, вставка, удаление, обход и балансировка.
- `Makefile` — сборка.

Узел дерева хранит контакт, уникальный ID и указатели на левого и правого потомка. Ключ упорядочения включает фамилию, имя, отчество и ID.

## Сборка и запуск

```bash
make clean
make
./phonebook
```

## Проверка функциональности

1. Пунктом `1` последовательно добавьте контакты с фамилиями: Алексеев, Борисов, Васильев, Громов, Дмитриев, Егоров, Жуков. Для каждого укажите имя, например Иван. Неприменимые поля можно оставить пустыми.
2. Выберите `5`: отображается структура дерева. При последовательной вставке упорядоченных фамилий дерево может вытянуться в одну ветвь.
3. Выберите `7`: отобразятся количество узлов, высота и сведения о балансировке.
4. Выберите `8`: запустится ручная балансировка. Повторите пункты `5` и `7` — структура станет компактнее, высота уменьшится.
5. Чтобы отдельно проверить автоматическую балансировку, запустите программу заново и выполните восемь успешных изменений (например, восемь добавлений), не вызывая ручную балансировку. После восьмого изменения сработает автоматическое перестроение; проверьте результат пунктами `5` и `7`.
6. Пунктом `6` выберите поле и алгоритм сортировки отображаемого списка (пузырьковая, выбором, вставками или быстрая). Пунктом `2` проверьте порядок контактов.
7. Пунктами `3` и `4` проверьте редактирование и удаление по указанному ID. После изменений повторно просмотрите список и дерево.
8. Пункт `0` завершает программу.

## Особенности

- Меньшие ключи размещаются в левом поддереве, большие — в правом.
- При удалении обрабатываются случаи узла без потомков, с одним и с двумя потомками.
- Балансировка выполняется через симметричный обход, массив узлов в порядке ключей и рекурсивное построение дерева от среднего элемента.
- Автоматическая балансировка запускается после восьми успешных изменений с момента последнего сброса счётчика.
- Пользовательская сортировка изменяет порядок вывода; внутренний ключ дерева остаётся прежним.
- Поиск по ID не обязан иметь логарифмическую сложность, поскольку дерево упорядочено по ФИО.
