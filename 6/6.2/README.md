# Задание 6.2. Динамическая библиотека

## Назначение

Логика телефонной книги вынесена в динамическую библиотеку `libcontacts.so`. Исполняемый файл `phonebook` использует эту библиотеку при запуске.

## Организация проекта

- `main.c` — интерфейс телефонной книги.
- `contacts.c` и `contacts.h` — реализация операций с контактами.
- `Makefile` — компиляция с `-fPIC`, создание `.so` с `-shared` и связывание программы с `-lcontacts`.

При компоновке задаётся `rpath` с `$ORIGIN`, поэтому загрузчик может найти `libcontacts.so` рядом с исполняемым файлом.

## Сборка и запуск

```bash
make clean
make
ls -l libcontacts.so phonebook
ldd ./phonebook
./phonebook
```

В выводе `ldd` должна присутствовать зависимость от `libcontacts.so` с разрешённым путём. В программе проверьте добавление (`1`), просмотр (`2`), редактирование (`3`), удаление (`4`) и изменение сортировки (`5`). Выход — `0`.

## Проверка зависимости от динамической библиотеки

После успешной сборки завершите программу и выполните:

```bash
rm libcontacts.so
ldd ./phonebook
./phonebook
```

Ожидаемый результат:

- `ldd` сообщает `libcontacts.so => not found`.
- `./phonebook` не запускается и выводит ошибку загрузки `libcontacts.so`.

Это ожидаемое поведение: библиотека требуется для запуска всего приложения. В отличие от плагинов задания 6.3, её удаление не отключает только одну команду меню.

Для восстановления:

```bash
make
ldd ./phonebook
./phonebook
```

После повторного создания `.so` приложение снова запускается.

## Особенности

- Код телефонной книги находится в отдельном разделяемом объекте `.so`.
- `ldd` позволяет проверить зависимость исполняемого файла.
- Для эксперимента библиотека удаляется после завершения процесса. Не запускайте `make` до проверки отсутствующей библиотеки: сборка восстановит её.
