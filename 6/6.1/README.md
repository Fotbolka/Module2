# Задание 6.1. Статическая библиотека

## Назначение

Логика телефонной книги из задания 4.1 вынесена в статическую библиотеку `libcontacts.a`. Исполняемый файл `phonebook` связывается с библиотекой при сборке.

## Организация проекта

- `main.c` — интерфейс телефонной книги.
- `contacts.c` и `contacts.h` — функции двусвязного списка и их объявления.
- `Makefile` — компиляция `contacts.o`, создание архива `libcontacts.a` и компоновка `phonebook`.

Статический архив создаётся командой `ar rcs` в ходе выполнения `make`.

## Сборка и запуск

```bash
make clean
make
ls -l libcontacts.a phonebook
./phonebook
```

Для проверки функций телефонной книги добавьте 2–3 контакта через пункт `1`, просмотрите их через `2`, измените сортировку через `5`, отредактируйте через `3` и удалите контакт через `4`. Завершите работу пунктом `0`.

## Проверка независимости готовой программы от статического архива

После успешной сборки и выхода из телефонной книги выполните:

```bash
rm libcontacts.a
./phonebook
```

Ожидаемый результат: программа продолжит запускаться, операции телефонной книги останутся доступны. Нужный машинный код уже включён в `phonebook` при компоновке. Сам архив для запуска готовой программы не требуется.

Для восстановления файла библиотеки выполните:

```bash
make
```

Дополнительная проверка:

```bash
ldd ./phonebook
```

`libcontacts.a` не будет показана среди динамических зависимостей. При этом системная `libc.so.6` может присутствовать: статически подключена именно библиотека контактов, а не все системные библиотеки.

## Особенности

- Реализация телефонной книги отделена от пользовательского интерфейса.
- Удаление `.a` после сборки не отключает функции готового исполняемого файла.
- Для повторной компоновки библиотека создаётся заново из `contacts.c`.
